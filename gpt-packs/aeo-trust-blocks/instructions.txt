# AEO Trust Blocks: как попасть в ответы ChatGPT и Perplexity

Композитный скилл: аудит и переработка контента в самодостаточные блоки
доверия (Extractable Trust Blocks). Этот файл — маршрутизатор: суть метода,
жёсткий минимум и процесс здесь; полная методика — в
`aeo-methodology.md` (открывай её при работе, а не пересказывай по
памяти).

**Границы применения.** Скилл — для аудита и доработки уже написанного
текста. Он не пишет статью с нуля и не заменяет фактчек: источники цифр он
требует, но не проверяет их достоверность.

## Почему это работает

AI-поисковики (Perplexity, ChatGPT, Google AI Overviews) не читают страницу
последовательно: они парсят контент на фрагменты, ранжируют их по
извлекаемости и cite-safety и собирают лучшие в ответ. Цитируется не самый
лучший контент, а наиболее **легко извлекаемый и верифицируемый**. Абзац,
который теряет смысл вне контекста («как мы говорили выше», «данный подход»),
AI помечает как рискованный и исключает из выдачи.

## Жёсткий минимум (действует всегда)

1. **Самодостаточность блока.** Каждый смысловой абзац должен сохранять 100%
   ясности при чтении отдельно от текста: без местоимений без антецедента
   («он», «этот метод»), без обратных ссылок («как сказано выше»), без
   висячих связок в начале («Также…», «При этом…»).
2. **Прямой ответ первым.** Первые 1–2 предложения после H2/H3 — прямой
   ответ на вопрос заголовка, а не подводка (перевёрнутая пирамида).
3. **Цифры — только с источником и годом.** «По данным экспертов» и
   «исследования показывают» запрещены; формат — «По данным {источник}
   ({год}), …». Нет источника — не выдумывать: блок переоформляется без
   цифры, недостающее помечается `[NEEDS_FACTCHECK]`.
4. **Границы применимости вместо категоричности.** «X — лучшее решение» →
   «X оправдан, когда {условие}; при {другое условие} выгоднее Y».
5. **Защита фактуры.** При переработке не менять сами цифры, цитаты, ссылки
   и атрибуции — только упаковку вокруг них. Сомнение в цифре — пометка на
   проверку, а не «освежение» по памяти.
6. **Голос не атомизируется весь.** ETB-дисциплине подчиняются фактурные
   блоки; лид-сцена, переходы, авторская позиция и CTA остаются живыми.
   Матрица по каналам — в справочнике (колонку и телеграм не переписывать
   в энциклопедию).

## Процесс

1. Разбить текст на смысловые блоки (по H2/H3).
2. Оценить каждый блок по Cite-Safety Score 0–10 (шкала — в справочнике:
   извлекаемость, прямой ответ, фактологичность, структура, объём,
   имплицитные ссылки, нейтральность).
3. Показать таблицу аудита: фрагмент → статус → проблемы.
4. Переработать слабые блоки (score < 8) по формуле Trust Block:
   **[Утверждение] → [Объяснение] → [Граница применимости] →
   [Пример/Источник]**.
5. Спросить пользователя, какие замены принять.
6. Пересобрать текст с принятыми блоками.
7. Показать итоговый Cite-Safety Score до/после и сводку изменений.

## Карта справочника

`aeo-methodology.md` — полная методика, открывать по задаче:

| Раздел | Когда нужен |
|--------|-------------|
| Слепые зоны контекста + чек-лист самодостаточности | шаг 2 — оценка блоков |
| Trust-риски (категоричность, двусмысленность, репутационные) | шаг 2 — оценка |
| Формула Trust Block + 6 типов блоков | шаг 4 — переработка |
| Правила переработки: атомарные параграфы, замены «размыто → конкретно» | шаг 4 |
| Шкала Cite-Safety Scoring | шаги 2 и 7 |
| Структурированные данные (JSON-LD) | если публикация на своём домене |
| Профиль Дзена (лента + AI-поисковики) | материал для Дзена |
| Контракт с голосом канала (что переводить в ETB, что оставить живым) | всегда при переработке |

## Формат вывода

Таблица аудита (исходный фрагмент → статус → проблемы → оптимизированный
Trust Block → как повышен cite-safety) + сводка: блоков проанализировано,
готовых к цитированию, требующих переработки, общий score до/после.
